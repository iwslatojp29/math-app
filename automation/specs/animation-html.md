## 1. 教材の目的と読者

読者は、中学受験の学習をしている小学4年生。割合・比・分数・面積など、受験算数の基礎知識はある前提とする。難問を避けず、**初見で解く糸口を探す力を育てる**。

完成形は、図を中心に講義を見ながら「どこを見るか → 何が分かるか → なぜその方法か → どう答えになるか」を短い説明で追える教材である。

最優先の品質は次の4点。

1. 数学的に正しく、結論に必要な論拠と数値の由来がつながっている。
2. 「どのように考えるか」「なぜそう考えるか」が分かる。
3. 図から読み取れることの実況や同じ理由の反復を省き、理解の速度を落とさない。
4. 読み上げている対象が、同時に図上で明確になる。

説明の字数・ステップ数・短縮率は固定しない。過去に作った問題数や短縮率を新しい教材の目標値として流用しない。

## 2. PDFの読み取りと対象範囲

### 2.1 全対象問題を確定する

- 指定された範囲は、大問・小問・図示問題・選択肢を含め、すべて扱う。「残りは同様」で解説を省かない。
- 問題抜粋PDFは、含まれる全問題を対象にする。「要点の整理」に載っている例題・問題も、掲載内容に応じて対象に含める。
- 冊子全体でも、範囲指定がなければPDF内の算数の問題・例題を対象とし、目次と紙面で欄を確認する。「日日の演習のための要点の整理」「日日の演習」「発展演習」「学力コンテスト」など、欄名の例示だけで対象を限定しない。解説中の単なる数値例を独立問題として水増ししない。この場合も**1PDF＝1HTML**とし、HTML内で欄を分ける。明示された範囲を勝手に拡張・縮小しない。
- 年月・号数・ページ・問題数は今回のPDFで確認する。冊子の印刷ページとPDF通算ページを区別する。
- 同じ問題番号が複数の欄にある場合は、内部IDを分ける。例：`points-5`、`practice-5`。番号だけをIDにしない。

制作中には「PDF名／欄／ページ／問題番号／小問／与件／求めるもの／答え」の一覧を作り、完成HTMLと照合する。管理用一覧を教材へそのまま掲載する必要はない。

### 2.2 原図と条件を確認する

- OCRだけに頼らず原画像を確認する。分数、小数点、単位、角度、比の順序、点名、直角・等長・平行の記号を照合する。
- 横向き・見開き・次ページへの続き・欄外の条件を確認する。
- 見た目だけで「中点」「直角」「平行」「同じ長さ」と決めない。与件・記号・導いた性質を根拠にする。
- 解くための条件を短く整理し、原問題画像もHTML内から開いて確認できるようにする。ページ全体を極端に縮めた画像だけにしない。
- 公式解答がなくても、条件を読めれば独立に解く。公式解答がある場合は実際に読み、全小問を照合する。答えに合わせるために条件を変えない。

## 3. 論理を保ち、冗長さを削る説明方針

### 3.1 必ず残す説明と、省く説明

| 必ず残す | 原則として省く・まとめる |
|---|---|
| 問題のどの条件に着目するか | 問題文の全条件を最初から逐語的に読み直すこと |
| なぜその補助線・比較・分割・断面を使うか | 点の並びや線の位置を、図で見える以上に実況すること |
| 結論に必要な性質と、その適用条件 | 既習の定義や公式を、使うたびに最初から教え直すこと |
| 相似の対応、同じ高さの根拠など、その問題固有の橋渡し | 一度説明した証明や高さの理由の反復 |
| 新しい数値・比・点・仮の目盛りの出所 | 計算を示した直後に、同じ結果だけを別の言葉で繰り返すこと |
| 解法が成立するために必要な場合分け・重複・取り残しの確認 | 明確な色分けで自明な単純分割を、形式的な完全性の文章で引き延ばすこと |
| 求めた量が設問の何に答えているか | 解答後の長い復唱、同じ結論の再確認、形式的な問いかけ |

**「論理の飛びをなくす」とは、全知識をゼロから証明することではない。** 既習の性質を使うときは、必要な性質と今回の対象を短く結び付ける。図で自明な位置関係の説明は減らしてよいが、図の見た目を未証明の等長・相似・直角の根拠にしてはいけない。

削除判断は次の順で行う。

1. この文を削ると、新しい数・式・結論の理由が追えなくなるか。追えなくなるなら残す。
2. この文を削ると、初見の子供がその方法を選ぶ理由が分からなくなるか。分からなくなるなら残す。
3. 直前の図・式・説明と同じ内容しか増えていないか。同じなら削るか統合する。
4. 一般論の長い講義になっていないか。今回の対象に必要な一文へ置き換える。

説明を短縮するために、未知の公式名や難しい用語だけで根拠を済ませない。全問題に定型の「確認」「注意」「まとめ」を大量追加しない。

### 3.2 解く糸口を教える

各問題の導入は、原則として短い1〜3文で次の内容をつなぐ。別々の大きな説明枠に分ける必要はない。

- 何を求めるために、どの条件を見るか。
- その条件から何がそろう・変わらない・比較できるか。
- 何をすれば、求めたい比や量につながるか。

例：「面積比を求めたいので、高さをそろえられる三角形を探します。Aから同じ直線BCへ下ろす高さは共通だから、底辺の比で比べられます。」

補助線は「引けば解ける」ではなく、「同じ高さの三角形を作るため」「対応する面を見つけるため」など、目的を先に示す。完成解を知っているから選べる補助線や数値を突然出さない。試行錯誤を見せる場合も、学習に役立つ短い試し方に整理し、制作中の探索ログは載せない。

### 3.3 論理を短くつなぐ具体例

**相似：条件 → 相似 → 必要な対応を続けて示す。**

条件が成立する問題で、単に「Bの角が共通で、PとEが直角です。したがって相似です」と終わらせない。例えば次のようにまとめる。

> 三角形ABPとOBEはBの角が共通で、PとEの角はともに直角です。2組の角が等しく、残りの角も180度から同じになるので、3組の角が等しい相似な三角形です。AとO、BとB、PとEが対応するので、ABとOB、BPとBEを比べます。

この内容を複数の短い発話に分け、該当する角・辺を順に強調する。既に相似の根拠を説明した同じ組について、比を使うたびに証明を繰り返さない。

**同じ高さ：比較対象と理由を特定する。**

> 三角形ABDとACDは、底辺BD・CDが同じ直線上にあり、頂点Aが共通です。高さが同じなので、面積比はBD：CDです。

同じ関係を再利用する箇所では、「先ほどと同じく頂点AからBCへの高さが共通なので、今回はBD：BCで比べます」のように短くつなぐ。

**仮の目盛り：扱いやすい数を選ぶ理由を示す。**

> 全体の4分の1と5分の2を比べたいので、全体を4と5の公倍数の20目盛りとします。

「全体を20」とだけ置かず、実際の20cmとも混同させない。

### 3.4 算数の方法と数値の根拠

- 主解法・別解とも、比、線分図、面積図、等積変形、分割、付け足し、逆算など、小学生が意味を追える算数で完結させる。
- 方程式・連立方程式・座標の代数計算・ベクトル・三角比・微積分・合同式で説明を済ませない。文字を□に変えただけの移項・代入も避ける。
- 同じ量を二通りに表す等式や、図で意味の分かる消去算は使ってよい。裏側の検算・作図座標の計算に高度な数学を使うことは妨げない。
- 新しい数値は「与件」「直前に求めた値」「仮の目盛り」「例の数」のどれか分かるようにする。式の意味を短く説明し、筆算の各桁まで読み上げない。
- 長さ比・面積比・体積比を混同しない。2乗・3乗・逆比にする場合は、対象と成立条件を示す。
- 図・式・文章・音声・答え一覧で、点名、比の順序、数値、分数、単位を一致させる。途中で不要な丸めをしない。
- 制作側では全小問を検算する。学習者向けには理解に役立つ検算だけを短く示し、同じ計算の再演を義務化しない。

## 4. 図形とアニメーションの設計

### 4.1 原図と解説図

- 原問題画像とは別に、考えるための解説図をSVG等で作る。正確さが必要な図形・点名・数値を、画像生成に任せない。
- 図形以外の問題では、数量関係の線分図・面積図、速さの移動図・時刻表、場合の数の樹形図など、考え方に合う表現へ置き換える。立体や相似の要件を、関係のない問題へ無理に適用しない。
- 原問題の点名を維持する。補助点は初出で定義し、原図の点と区別する。
- 同じ対象は同じ色で表し、本文・音声・図で対象名をそろえる。青と橙などの比較色を使う場合も、点名や線種を併用する。
- 角の比較には角印、直角には直角印、高さには底辺への垂線、対応辺には同色の線・対応表示を使う。三角形全体を塗るだけで、どの角が等しいか分からない状態にしない。
- 与えられた条件と、後から求めた値を識別できるようにする。未導出の答えを最初の図へ先回りして表示しない。
- 立体は、辺・面・奥行き・隠れ線・切断面の関係を正しく描く。必要に応じて、計算用の平面図を取り出し、元の立体のどの面・断面か対応させる。
- 立体の斜めの辺を垂直な高さと扱わない。見取図の見かけの直角と、空間上の垂直を区別する。

### 4.2 動かす目的

アニメーションは、補助線の追加、対応する辺や角、平行移動、折り返し、切り口、分割・組み替えなど、**静止画では追いにくい関係を理解するため**に使う。

- 説明の順に必要な対象を出し、読み上げに合わせて強調する。
- 移動・折り返しで何が変わらないかを、元の位置と移動後の対応から示す。比較用に離して置いた図を実際の位置関係と誤解させない。
- 元図の薄い輪郭や点名を残し、移動後に元の場所が分からなくなることを防ぐ。
- ループする飾り、過剰な点滅、不要な回転は付けない。動きを減らす設定でも、静的な強調と説明で理解できるようにする。
- 合同・相似・面積保存・体積保存など、動かして見せたことを数学的な根拠の代用にしない。必要な性質を短く言葉でも示す。

### 4.3 枠を生かして大きく表示する

- 図の枠だけを大きくし、中の図を小さいまま残さない。
- 図形・ラベル・補助線・矢印・動きの範囲を含めた実際の描画範囲にSVGの`viewBox`を合わせ、不要な余白を詰める。
- 縦横比は維持する。横長の枠へ縦長図を無理に引き伸ばさず、枠の高さや図の配置を調整する。
- 一つのステップ内では、後から現れる補助線や移動範囲まで含めた表示範囲を先に確保する。発話が変わるたびに図が拡大縮小・移動して目で追えなくならないようにする。
- 主要ラベルは通常倍率で読める大きさにする。表示上14〜16px程度以上を出発点とし、実画面で調整する。
- 文字、数値、角印、矢印の重なりや端の欠けを確認する。`overflow:hidden`で切り落として解決しない。

## 5. 問題ごとの講義と見直し操作

### 5.1 問題番号から一つの講義を通して見る

- 各問題に独立した「図で見る講義」を設ける。
- 左の問題番号を押すと、その問題を表示し、冒頭から最後の小問の答えまで順に再生する。既に別の問題が再生中なら停止して切り替える。
- 初めてファイルを開いた時点では勝手に発声せず、問題番号・再生ボタン等の利用者操作を起点にする。
- 問題の最後で止める。別の問題を自動で読み続けない。再度同じ問題番号を押した場合は冒頭から始める。

### 5.2 ステップと発話を分ける

- **ステップ**：着眼点、補助線、相似、計算など、考え方のまとまり。
- **発話**：一つの見る対象・論点に対応する短い説明。内部データではcue等と呼んでもよい。

一つのステップ内に複数の発話を持てるようにする。細かすぎるステップを大量に作らず、一方で長い段落を一度に読み上げて図が追えない状態にもせず、説明対象の変化に合わせて区切る。

- 再生／一時停止／再開、前後の説明へ移動、今の説明の再生、問題の最初から再生を用意する。
- 任意のステップを選ぶ小さな選択欄を、上の操作行に置く。現在のステップ位置も分かるようにする。
- 小問が複数ある場合は、小問の選択も用意する。小問を選んだ場合は、その小問に必要な前提から答えまで再生する。
- 前の小問の結果が必要なら、選択再生に必要な導出ステップを組み込むか、その結果と出所を明記する。初見で必要な根拠が不明なまま答えだけ流用しない。
- 任意の途中へ移動したときは、そこまでに確定した補助線・比・値を復元し、現在の説明に必要な前提を図や短い表示で分かるようにする。毎回長い復習を読み上げる必要はない。
- 前へ戻っても図が崩れず、何度でも同じ状態から見直せるようにする。

**独立した大きな「好きなステップから見直す」セクションは作らない。任意ステップへ戻る機能は、上部のコンパクトな操作欄に残す。**

## 6. 音声・表示文・図の同期

### 6.1 一つの発話を同期の単位にする

各発話に、少なくとも次を対応付ける。

| 項目 | 内容 |
|---|---|
| 表示文 | 子供が読む自然な日本語。漢字・点名・式を通常表記する |
| 読み上げ専用文 | 正しい読みと自然な語順に直した音声用の文 |
| 注目対象 | SVG内の辺・角・点・面・数値等の対象ID |
| 図の状態 | 表示する補助線、強調、移動、式・数値の出現 |

表示文と音声を別々に作って放置せず、意味・点名・数量・順序を全件照合する。

- 発話開始時に、その発話の図・強調・字幕を表示する。前の発話の図のまま次の音声を流さない。
- 音声終了を確認して、次の発話へ進める。長文を一度に読み、文字数から推定した固定タイマーだけで図を切り替える方式は使わない。
- 一つの発話で注目箇所が大きく変わるなら、発話を分割する。語単位のイベントが使える場合も、端末で提供されない場合に備える。
- 一時停止中は、図と字幕をその説明の状態に保つ。再開が不安定な端末では、現在の短い発話を先頭から再生して整合させる。
- 問題・小問・ステップを変えたときは、旧音声・タイマー・アニメーションを停止する。古い終了イベントが後から届いて新しい問題を進めないようにする。
- 再生速度変更時にも、現在位置と説明対象を維持する。必要なら現在の発話を新しい速度で再開する。
- 音声なしでも、同じ図・字幕を手動で順に見られるようにする。無音の自動再生を付ける場合は、読める表示時間と速度設定を反映する。

### 6.2 全ての読みを確認する

「中点」だけ直すような個別対応で終わらず、**全発話の用語、漢字、点名、数字、助数詞、式、単位を確認する**。単純な漢字置換・自動ふりがなだけで完成扱いにしない。

読み上げ専用文は、原則として確認済みのかな・カナを主体とし、記号・式を自然な日本語へ展開する。通常表記の表示文はそのまま読みやすく保つ。

| 表記 | 読みの例 |
|---|---|
| 中点／頂点／交点 | ちゅうてん／ちょうてん／こうてん |
| 相似／合同／垂直／平行 | そうじ／ごうどう／すいちょく／へいこう |
| 底辺／底面／側面／斜辺 | ていへん／ていめん／そくめん／しゃへん |
| 対角線／対頂角／錯角 | たいかくせん／たいちょうかく／さっかく |
| 二等辺三角形／正六角形／正八面体 | にとうへんさんかくけい／せいろっかくけい／せいはちめんたい |
| 三角すい／三角柱／体積 | さんかくすい／さんかくちゅう／たいせき |
| 三組／三個／四本／六本 | さんくみ／さんこ／よんほん／ろっぽん |
| 点A／辺AB／三角形ABP | てんエー／へんエービー／さんかくけいエービーピー |
| 角ABC | かくエービーシー。頂点Bを図で強調する |
| AとO、BとB | エーとオー、ビーとビー。Oと数字の0を混同しない |
| 3：1／3÷2／3×2 | さんたい いち／さん わる に／さん かける に |
| 3/4／1と1/2／0.25 | よんぶんの さん／いちと にぶんの いち／れいてん に ご |
| 6cm／3cm²／2cm³／90° | ろくセンチメートル／さんへいほうセンチメートル／にりっぽうセンチメートル／きゅうじゅうど |

この表は出発点であり、辞書掲載語だけを確認すればよいという意味ではない。新しい語や固有名、複合語、数の読み方はその都度点検する。数字・単位を一律に機械変換せず、「1つ・1本・1組」など文脈に合う読みを確認する。分数の分子・分母を逆転させない。

### 6.3 自然な声と再生速度

- 自然な日本語の語順と句読点にする。短すぎる単語ごとの発話、過剰な間、抑揚を狙った記号の乱用を避ける。
- 利用可能な日本語音声から、聞き取りやすい音声を自動選択する。音声一覧の取得が遅れる場合にも対応する。
- **「音声を選ぶ」欄は作らない。** 音声の有効／無効はコンパクトなボタンで切り替えられるようにする。
- 音声速度は **1.00、1.25、1.50、1.75、2.00、2.25、2.50、2.75、3.00倍**の9段階。初期値1.00倍。図の進行も音声に追従させる。
- 標準の実装はブラウザの日本語読み上げ等、HTMLを開いて使える方式とする。有料サービス、別サーバー、利用者のAPIキー入力を必須にしない。
- 声質・厳密な実時間倍率・オフライン発声の可否は端末や音声エンジンに依存する。設定した倍率を全端末共通の実測値として保証しない。
- 日本語音声がない場合や音声が失敗した場合は、短い状態表示とともに、字幕・図・手動操作で学べる状態を保つ。読み上げ中のまま操作不能にしない。
- 試聴できる環境では代表的な発話を実際に聞く。文字の読み点検、音声イベントの自動検証、実際の試聴を区別し、試聴していないものを「全音声を試聴済み」と書かない。

## 7. 全HTMLで統一するUI

### 7.1 画面の構成

| 領域 | 必須仕様 |
|---|---|
| 最上部 | 文字サイズ調整と各種操作をまとめた、固定表示のコンパクトな1行 |
| 左側 | 狭い問題番号一覧。目安幅64〜88px。本文側とは独立した縦スクロール |
| 右側 | 講義・解説の主領域。左側とは独立した縦スクロール |
| 講義の図 | 横置き時、主領域内の講義幅の約2/3 |
| 講義の説明 | 横置き時、残り約1/3。現在の発話、必要な式、短い見出しを表示 |

- 左は「要点」「演習」等の短い区分見出しを付け、各リンクの表示は原則「5」など**問題番号だけ**にする。長い問題名や説明を並べて幅を広げない。複数欄がある場合も同様に区分する。
- 選択中の番号を識別できるようにする。左右のスクロールバーを用意する。OSがバーを自動非表示にする場合にもスクロール操作は成立させる。
- 全体の上端をスクロールさせず、文字サイズ調整を常時見える位置に置く。固定ヘッダーが見出しや図を隠さないようにする。
- 2/3：1/3はサイドバーを除いた講義領域の配分とする。図と説明の関係が一目で追える距離に置く。
- 説明欄が長い場合はそこでスクロールできるようにし、文字を小さくして詰め込まない。現在の発話が見えるように更新する。

### 7.2 操作は上の1行へ集約する

同じ操作をあちこちに重複配置しない。例えば次の順でまとめる。

`文字 小・標準・大 ｜ 再生/停止 ｜ 前へ・次へ ｜ 今の説明を再生 ｜ 最初から ｜ 小問 ｜ ステップ ｜ 速度 ｜ 音声ON/OFF`

- 短い表示やアイコンを使い、操作に使う縦幅を節約する。表示を短くしても、読み上げ名・説明でボタンの意味を明確にする。
- iPad横置きで複数段に並ぶ大きな操作パネルを作らない。ボタンの間隔、選択欄の幅、重複を調整して1行に収める。
- 狭いスマートフォンでは、操作行だけの横スクロールを許容する。ページ全体・本文・主図の横スクロールは生じさせない。
- タッチ操作できる大きさを確保し、文字サイズ変更後も操作部が欠けないようにする。本文の拡大によってボタンまで過大になる実装を避ける。
- 「好きなステップから見直す」「音声を選ぶ」という独立セクションは置かない。

### 7.3 図・文章・静的解説

- 本文は18px前後、行間1.7〜1.9程度を出発点とし、通常倍率で調整する。日本語フォントは丸ゴシック系を優先し、代替フォントを用意する。
- 白を基調に、強調色を必要な対象へ使う。大きな見出し、飾り、広すぎる余白で図の高さを奪わない。
- 講義の下、または読み返せる静的領域に、図・理由・式・各小問の答えを残す。音声を聞けない環境でも、解答への道筋が読めるようにする。
- 全小問の答え一覧も設け、欄・問題番号・小問番号・単位を対応させる。講義開始前に答えを強制表示する必要はない。
- 静的解説も、講義と矛盾しない簡潔な内容にする。以前の誤った理由や古い数値を残さない。
- 原画像、必要な補足、別解の詳細は折り畳んでよいが、主解説の成立に必要な根拠を隠さない。
- 追加の類題や口頭確認は、主要な着眼点を確かめる価値がある場合だけ短く置く。全ステップに問いかけを付けたり、講義を長くするために追加したりしない。依頼のない宿題計画・誤答台帳・正答率予想は付けない。

### 7.4 画面幅と印刷

- iPad横置きは図と説明を2：1で並べる。縦置き・狭い画面では、図を上、説明を下へ切り替えてよい。左の一覧は狭い幅を保つ。
- 図の全体縮小だけではみ出しを解決せず、注釈の整理、段階図、縦配置、表示範囲の調整を先に行う。
- 印刷時は操作部を除き、全対象問題の静的な解説・必要な図・答えをA4で読めるようにする。選択中の問題だけを印刷する状態にしない。折り畳みを開き、印刷後は元の状態へ戻す。

## 8. 単独HTMLとしての実装条件

- `<!doctype html>`、`lang="ja"`、UTF-8、viewportを設定する。
- CSS、JavaScript、解説図、必要な問題画像、講義データをHTMLに内包する。相対パスの別ファイル、外部CDN、外部フォント、外部画像、数式レンダラーを必須にしない。
- 本文・図・式・静的解説は、ネット接続やサーバー起動なしで表示できるようにする。音声については前述の端末依存を扱う。
- 数式は確実に描画できるHTML/CSS等で表し、未処理の`\frac`や`$...$`を残さない。
- 問題・小問・ステップ・発話をデータとして管理し、表示文、読み、図の対象、式を関連付ける。対象の参照先が存在することを検証する。
- SVGのマーカー・クリップ・図形IDはHTML全体で重複させない。図ごとのCSSを適切に限定する。
- grid/flexの子要素には`min-width:0`等を設定し、長い式や選択欄で横幅が押し広げられないようにする。
- 巻き戻しでは履歴に継ぎ足すだけにせず、指定ステップの正しい図の状態を復元できる構造にする。
- ボタン・選択欄はキーボードでも操作でき、フォーカスを表示する。図の代替説明も付ける。重要情報をマウスオーバーだけで表示しない。
- 問題を切り替えても文字サイズ・音声ON/OFF・速度は保持する。端末内保存を使う場合、保存が拒否されても動作を継続できるようにする。
- データ数を過去の特定教材に固定しない。PDFごとの問題数・小問数・図の数に対応する。

## 9. 制作と検証の手順

### 9.1 制作順序

1. PDFと対象一覧を照合し、全小問の条件・求めるものを確定する。
2. 全問を独立に解き、答えだけでなく解法が成立する理由を確認する。
3. 各問題について、着眼点・方法を選ぶ理由・必要な導出・答えを整理する。
4. 「必要な理由がない箇所」と「既に分かることの繰り返し」を別々に点検し、短い講義へ再構成する。
5. 図・ステップ・発話・読み上げ文・ハイライトを対応させる。
6. HTMLを作り、静的な読み返し用解説と答え一覧も一致させる。
7. 下記を確認して修正し、完成HTMLを保存する。

### 9.2 数学と教材内容の検証

- 全大問・小問の収録と答えを対象一覧で照合する。
- 各小問を適切な方法で検算する。答えが公式解答に一致するだけで、途中の論理も正しいと判定しない。
- 相似・合同の条件、対応順、面積や体積の比、垂直な高さ、分割の重複・欠け、境界・例外を確認する。
- 必要な場合は別の検算や独立した読み直しを行う。複雑な図の見た目だけで正しさを判断しない。
- 新しい数・点・比を、説明前に突然使っていないか確認する。
- 解法選択の理由を削って、計算手順の実況だけになっていないか確認する。
- 本文・静的解説・図・式・音声・答え一覧を照合する。
- 各小問の選択再生で、前の小問にしかない前提が抜け落ちていないか確認する。

### 9.3 音声と操作の検証

- 全発話の読みを点検し、用語・点名・数値・単位・助数詞の読み違いを修正する。
- 全発話について図の対象と表示文を照合する。話している辺や角と違う箇所を強調していないか確認する。
- 全問題番号から、問題の冒頭〜最後の答えまで再生経路がつながることを確認する。
- 全小問の独立再生、ステップ移動、前後移動、同じ発話の再生、一時停止・再開を確認する。
- 再生中に別問題や別ステップへ移動しても、旧音声や終了イベントが混ざらないか確認する。
- 9段階の速度、音声ON/OFF、音声未対応時の操作を確認する。
- 実際の試聴が可能なら、専門用語・点名・分数・長い式を含む発話と速度変更を試す。模擬音声イベントによる確認を、発音・声質の試聴と取り違えない。

### 9.4 実表示の検証

ソース確認だけで終わらず、利用できるブラウザで完成HTMLを実際に開く。

| 表示領域の目安（CSS px） | 確認内容 |
|---|---|
| 1024×768 | 狭めの横画面、1行操作部、図と説明の2：1配分 |
| 1194×834 | iPad横置きを想定した図の大きさ・ラベルの可読性 |
| 1366×1024 | 広い画面でも図が小さく残らず、余白が過大でないか |
| 幅768前後 | 縦配置への切替、左右のスクロール |
| 幅390前後 | 操作の到達性、本文・主図の横はみ出し |

- 通常文字サイズと最大文字サイズを確認する。
- 図の端、角印、補助線、移動後の図、最も密な立体、最も長い説明を点検する。
- ページの横はみ出しは寸法でも確認する。ただし、SVG内の重なり・小さすぎる文字は寸法検査だけでは分からないため、画像としても見る。
- 固定操作部、左右それぞれのスクロール、番号からの移動、原画像、印刷を確認する。
- ファイル単独での画像・図・式の表示と、JavaScriptの実行時エラーを確認する。
- 不具合を直したら影響する箇所を確認する。意味のない回数の再テストは重ねない。

ブラウザの画面幅を合わせた確認を「iPad実機確認」と呼ばない。音声・実表示・実機確認など、実施できなかった確認は納品時に短く明記する。問題の判読・答え・説明に重大な未解決事項がある場合は完成版と呼ばない。
