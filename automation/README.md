# 月間号PDFのクラウド処理

## SAPIX の追加取り込み

SAPIX の「更新」から `/studio/sapix-import` を開き、候補を選んで確認してから取り込みます。既存の教材スタジオの管理者用 Drive 接続を使用します。採点用の Gmail 接続とは別です。API キーは Worker の `ANTHROPIC_API_KEY` シークレットに置き、ブラウザへ返しません。

対象は固定 Drive フォルダ `1f1AhUw8Yciyye8V1_eZbvTBGlpQU0EyO` とその子フォルダにある PDF・PNG・JPEG・WebP です。初回の日時判定は **2026年9月24日 0:00 JST 以降のファイル作成日時**を使います。古いファイルを移動した日時は判定できません。取り込み台帳の Drive ID で再取り込みを防ぎます。

一度に10ファイルまで選択できます。最新の利用可能な Claude Fable を Models API で調べ、確認時のモデルと資料の版をジョブへ固定します。`sapix-import.yml` が小問ごとに抽出・検算し、固定テンプレートに渡す JSON と画像を単一コミットで追加します。秘密値・中間結果・元 PDF を Actions artifact に残しません。原画像は公開される教材の出典画像として保存します。

資料が変わった場合や読み取り・答えに未解決事項がある場合は、選択したバッチ全体を公開せず履歴に理由を表示します。既存の問題・採点を置き換えません。生成済みのチェックポイントを再利用し、Pages への反映確認後に完了を表示します。1ファイル100MiB・100ページ、バッチ全体で出典画像100枚・64MiBまでです。

既存問題は `sapix/problem-parts.js` で小問ごとに表示します。元の問題の ID と記録は保持し、小問には安定した別 ID を付けます。分割前の一括採点は「情報・履歴」に表示し、小問の成績には流用しません。

```sh
python -m unittest discover -s automation/tests -p test_sapix_import.py
node --test tests/sapix-generated-problems.test.cjs tests/sapix-problem-parts.test.cjs
node --test proxy/test/sapix-import.test.mjs
```

## PDF切り出しと解答解説HTML作成

算数一覧の「更新」から Studio を開き、作業を選択します。資料の選択だけでは処理を開始しません。それぞれの専用実行ボタンを押すと、選択した処理だけを実行します。

- **PDFを切り出す**: 元の月間号を選び、API経由のAIによる範囲判定・独立再検証を経て、日日系と発展・学コン系のPDFを固定Driveフォルダへ保存します。ここで完了し、HTML作成や公開は開始しません。
- **解答解説HTMLを作成する**: 固定の日日系・発展系フォルダに保存済みの切り出しPDFを1本選びます。そのPDFの全問を対象にHTMLを1本作成し、Drive保存とPages公開を確認します。元の月間号の再解析やPDF切り出しは行いません。

`monthly-pdf.yml` は `workflow_dispatch` の `job_id` だけを受け取り、Workerからジョブに固定された `operation` (`extract` / `html`)・入力資料・モデル・仕様を取得します。ブラウザを閉じても処理はGitHub Actionsで継続します。

```text
PDF切り出しボタン → 元PDF取得 → 全ページ画像確認・独立再検証
                  → 2種類のPDFを元ページから複製 → 全ページ画素照合
                  → Drive保存確認 → 完了

HTML作成ボタン → 選択済みの切り出しPDF取得 → 全問一覧・公式解答との照合
               → 問題単位の講義生成 → 独立した数学・読みの検証
               → 固定renderer → ブラウザQA・画面画像確認 → Drive HTML保存
               → WorkerによるPagesコミット → 公開内容のSHA-256確認 → 完了
```

新規ジョブのAPIには `operation` が必須です。旧画面から作業指定なしで一括実行を始める要求は受け付けません。旧ジョブはPDF切り出しとして再開し、旧runnerがHTML生成・公開へ進もうとした場合は保存済み成果物を残して停止します。完成済みの旧HTMLへのリンクは履歴に残ります。

Python 3.12、Node.js 24、`requirements.txt`、PlaywrightとChromiumを使用します。入力資料と仕様書の指示を区別し、PDF本文を実行命令として扱いません。生成モデルは `job.model` をそのまま使用し、モデルを自動で置き換えません。

実行環境には `STUDIO_URL`、`STUDIO_RUNNER_TOKEN`、`OPENAI_API_KEY`、GitHubの `GITHUB_RUN_ID` が必要です。秘密値はActions Secretsから環境変数として渡します。`GITHUB_TOKEN` はworkflow組込みトークンですが、教材の公開はWorkerに保存されたGitHub資格情報で行い、Pagesの通常の更新を起動します。秘密値や元PDFをリポジトリに追加しないでください。

```sh
python automation/run_monthly.py --job-id "$JOB_ID"
```

再開時は同じジョブを使います。ResponsesのリクエストID・検証結果とDriveの予約ファイルIDをprivate checkpointへ保存するため、完了済み生成の再課金やタイムアウト後の重複保存を避けます。checkpointにはトークン、アップロードセッションURL、元PDF、画像のbase64を保存しません。途中のPDF、画像、教材JSON、ブラウザ画面は一時ディレクトリのみで扱い、Actions artifactにアップロードしません。

新しく保存する検証済み生成結果は、APIが返したJSONを `resultJson` 文字列として保持します。WorkerのJavaScriptを通る際も小数・負のゼロ・大きな整数・キー順序が変わらず、再開後の検算リクエストが別物と判定されることを防ぎます。読み込み時にもschemaを検証します。従来の `result` 形式はそのまま読み込み、保存上限を超える結果は既存のResponses IDから取得します。

独立検証が図形一覧の文字注釈を「一つもない」などと指摘し、実データでもlabelが0件の場合は、原画像とcueから文字が必要な要素だけを選び、文字専用schemaで修復します。レビューに英語の図形型名や全IDの列挙を求めず、可視line/polylineの実データを確認します。正当な矢印・図形は残し、文字の取り残しと全小問の数学を独立検算してから採用します。新規API呼び出しには、ID・字幕・線から図中文字が自動生成されることはなく、実際のlabel/textが必要であることを明示します。

最初の進捗更新で `GITHUB_RUN_ID` を担当実行として登録し、以後は `X-Studio-Run-Id` を付けます。停止済み・別実行が担当するジョブへの409応答では状態を書き換えず終了します。生成中のResponsesは同じIDを取得し直し、終端の失敗・未完了状態になったResponsesだけは再開時に新しく生成します。

一時的な通信障害はWorkerの自動再開対象として報告します。1回の実行が300分に達した場合も、ResponsesのIDと保存状況を残して次のクラウド実行へ引き継ぎます。数学・範囲・保存先の検証で保留したものは自動再試行せず、確認が必要な状態を表示します。

図の欠落参照を補う修復で、追加要素の寸法が構造検査に拒否された場合は、その追加要素だけを対象とする修復を最大2回追加します。原画像に基づいて再生成し、既存図形・問題条件・答えを維持したまま構造検査と独立検算を通します。幅を固定値に置き換えたり、検証を省略したりしません。既存の生成・検証チェックポイントは再利用します。クラウドの自動再開待ちは画面でも区別し、再開後の進捗取得を継続します。

この追加修復の出力schemaには、rendererと同じ正の寸法条件とラベル文字サイズ14以上を数値制約として指定します。従来の通常生成・参照修復2回のschemaは保持し、追加修復だけ別のチェックポイントとして扱います。数値制約は[OpenAI Structured Outputsの対応仕様](https://developers.openai.com/api/docs/guides/structured-outputs)に基づき、応答受信後にも検証します。

参照修復後の独立検証が「文字が必要なのに不可視の折れ線を追加した」と指摘した場合は、追加したIDだけを対象に、原画像に基づく文字対象の識別とlabel専用schemaでの修復へ進みます。元からあった図形や不可視アンカーは変更しません。対象全件の根拠、可視の文字データ、全小問の独立検算がそろわない場合は保留します。

独立検証が実在IDを挙げて必須文字の欠落を指摘した場合は、文字代わりに作られた可視の折れ線も、別の識別工程で確認します。線の色や短さだけで文字だと決めず、原画像・発話・表示cueの根拠を要求し、正当な矢印や枠線を除外します。指定した要素だけを実ラベルに置き換え、全小問の独立検証を通します。

指摘が「線分」「折れ線」と書かれる場合も、実際の `line` / `polyline` データから文字対象を識別します。従来の英語 `polyline` 指摘に対応する要求は保持し、新たな対象だけ別の修復チェックポイントを使います。正当な矢印・辺・枠線を文字化した場合は独立検証で拒否します。

個別IDを列挙せず「図形一覧全体が線で文字注釈がない」と指摘された場合は、実候補にもlabelがないことを確認してから、表示される線要素を原画像に基づく識別へ渡します。全図形を文字と決めつけず、文字が必要だと確認できた対象だけを修復し、独立検証で文字の取り残しと矢印・枠線の誤変換を確認します。

個別問題の自己検証が、同じページに写る別問題の続きや全体のページ管理を確認できず保留した場合は、検証済みの全問一覧・公式解答の対応と、隣接問題の続き・解答画像を追加し、最大2回再確認します。追加画像は補助資料として扱い、対象問題の原画像IDと全小問を維持します。生成側と独立検証側の両方が実画像を確認し、対象問題の不足や数学的な疑義が残る場合は公開を保留します。既存の生成応答と完成済みの別問題は再利用します。

隣接問題は本文だけでなく公式解答ページの重なりからも選びます。前問の解説だけが写る場合も、その本文・解説前半の画像と受理済みの照合根拠を補足します。この接続確認では元の画像に直接つながる問題を固定し、補助画像に写り込むさらに別の問題へ範囲を再帰的に広げません。対象問題と直接つながる部分の実際の不足・矛盾は引き続き保留します。

全体の収録確認による保留は「PDF全体」「教材全体」「全28問一覧」などの言い回しでも検出します。収録・一覧・ページ対応の不足が同じ文にある場合に補助確認へ進み、図全体の面積や答えの不一致だけではこの経路を起動しません。補助確認後も独立検算の承認を必須とします。

新規の個別生成・独立検算API呼び出しには、全問一覧と公式解答の対応が先行工程、全問の収録照合が統合工程の担当であることを明示します。各呼び出しは担当問題の全小問と必要なページ接続を検証し、具体的な不足・矛盾は引き続き保留します。この工程説明は新規POSTだけに適用し、保存済みの結果・未完了の応答IDを引き継ぎます。

通常生成・文字修復・参照修復の独立検算で初めて全体の収録確認が否認理由になった場合も、既存の試行を終えてから同じ管理情報と補助画像で再検証します。構造検査に合格した候補を固定し、元の検算結果と指摘を全文保持したまま、各問題につき全経路で合計2回まで独立検算を追加します。全小問の照合と根拠がそろった承認だけを受理し、数学の疑義・確認漏れ・原画像不足は保留します。

処理中の冊子が更新された場合、対象範囲・重要な問題条件・数学の検証に未解決事項がある場合、既存ファイルの編集者や内容を特定できない場合は、該当成果物の公開を保留します。正しい既存PDFは全ページ画像で照合して再利用できます。管理済み成果物を更新する場合は、元のDriveファイルIDを維持し、手動編集された内容を上書きしません。

HTMLは1切り出しPDFにつき1本、24MiB以内です。ファイル名は選択したPDFの拡張子を除いた名前に `_講義アニメーション.html` を付けます。既存の一括処理で作ったHTMLを更新する場合は、過去ジョブの出力PDF・HTMLと今回の入力PDFとの対応、保存先、所有情報、内容の未変更を照合してから引き継ぎます。容量超過時に問題を省略したり、勝手に分割したりしません。ブラウザの寸法検証・模擬音声イベントと、実機試験・実音声の試聴は区別して結果に記録します。

オフライン検証:

```sh
python -m unittest discover -s automation/tests -v
node --test automation/renderer/renderer.test.mjs
```

Pythonの統合テストは公開用の幾何問題fixtureを使い、PDFの実抽出、全ページ画素照合、全問データ生成、実際のNode.js renderer CLI、自己完結HTMLの出力まで通します。外部API・Drive保存・公開・ブラウザQAはこのテストでは模擬応答です。ブラウザの実検証は `renderer/verify-lesson.mjs` が行います。

API実装の参照: [Responses background mode](https://developers.openai.com/api/docs/guides/background)、[Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)、[Google Drive resumable uploads](https://developers.google.com/workspace/drive/api/guides/manage-uploads)。PDFの範囲・命名・品質基準は同梱された `specs/extract-pdf.md` と `specs/animation-html.md` を実行ごとに読み込みます。
